# PixelTris · 像素沙粒消除

一个网页版方块游戏：**俄罗斯方块的落块手感** ＋ **方块落地即炸成沙粒** ＋ **同色沙粒连通左右即消除**。

## 玩法

1. 方块从顶部下落，左右移动、旋转。
2. **落地瞬间整个方块炸成沙粒**——不保留方块形状，36 颗（6×6）小颗粒直接灌进沙堆。
3. 沙粒受重力约束，会**顺着坡度往两边低处溜**，堆出自然的沙丘斜面。
4. **消除规则不是消行**：同色沙粒连成一片，并且这片**同时贴住最左边和最右边**，整块消除。
   - 判定是上下左右四方向相邻，斜着挨着不算。
   - 只要被异色切断一格，就算断开。
5. 消除后上方沙粒继续塌落，会引发**连锁**，连锁越多次倍率越高。

## 本地运行

纯静态，无构建步骤、无依赖，**双击 `index.html` 就能玩**。

想用本地服务器：

```bash
python -m http.server 8123 --bind 127.0.0.1 --directory .
```

然后打开 http://127.0.0.1:8123

## 内部结构说明

- **双坐标体系**：方块用「格」（10×20），沙粒用「颗粒」（80×160）。一格 = 8×8 = 64 颗粒。
- **网格存的是 `Uint8Array(80*160)`**，0 表示空，n 表示颜色序号 + 1。
- **沙粒规则**：自下而上扫，能往下就往下；下面被占就随机挑一侧斜下方溜。这就是斜坡的成因。
- **流动距离限制**：每颗粒子带一个滑行计数，横向最多溜 `MAX_SLIDE` 次就停住（掉下去不计）。这是控制「沙子摊得多开」的旋钮。
- **渲染**：每帧把颗粒网格写进 80×160 的 ImageData，再以最近邻放大到画布。比逐格 `fillRect` 快得多，而且边缘天然是硬像素。
- **消除时机**：沙子**完全稳定**（连续 3 个物理步没有颗粒移动）后才判定，避免半空中误消。

## 常用调参

| 想改什么 | 位置 |
|---|---|
| **沙子摊多开** | `core.js` 的 `MAX_SLIDE`（1=很陡，2=默认，6 以上会摊到边上） |
| 颗粒精细度 | `core.js` 的 `SUB`（越小越粗，越大越细，8 是手感与性能的折中） |
| 棋盘尺寸 | `core.js` 的 `COLS` / `ROWS` |
| 颜色数量 | `core.js` 的 `COLORS`（加减几项都行，方块颜色自动循环） |
| 沙子流速 | `game.js` 的 `STEP = 1/67`（**调大=变慢**，调小=变快） |
| 下落速度曲线 | `game.js` 的 `dropInterval()` |
| 锁定延迟 | `game.js` 的 `lockDelay` |
| 得分公式 | `game.js` 的 `doClear()` 里 `particlesCleared * 2.5 * chain` |
| 升级速度 | `game.js` 的 `level = 1 + Math.floor(clears / 6)` |

想对比不同 `MAX_SLIDE` 的效果，可以直接跑诊断脚本：

```bash
node tests/diag.js
```

它会用同一组 12 个方块分别按 `MAX_SLIDE = 1/2/3/6/99` 模拟，打印每列高度。

## 已知取舍

- 沙粒是格子化的沙堆模型（45° 休止角），不是真实刚体物理。
- 方块下落时仍是硬方块，落地那一瞬才溶解——这是为了保留俄罗斯方块的可操作性。
- 没有 Hold（暂存）、没有多块预览。
- 最高分存在 `localStorage`，清缓存会丢。
