# PixelTris · 像素沙粒消除

一个纯静态的网页小游戏：**俄罗斯方块的落块手感** ＋ **方块落地即炸成沙粒** ＋ **同色沙粒连通左右即消除**。

无构建步骤、无依赖、无外网请求，双击 `index.html` 就能玩。

---

## 玩法

1. 方块从顶部下落，左右移动、旋转。
2. **落地瞬间整个方块炸成沙粒**，不保留方块形状：一格 = 16×16 = 256 颗粒，一个四格方块落地会灌进去 **1024 颗粒**。
3. 沙粒受重力约束，会**顺着坡度往两边低处溜**，堆出自然沙丘。
4. **消除规则不是消行**：同色沙粒连成一片，并且这片**同时贴住最左边和最右边**，整块消除。
   - 相邻判定是上下左右四方向，斜着挨着不算。
   - 中间被异色切断一格，整片就不算连通。
5. 消除后上方沙粒继续塌落，会引发**连锁**，连锁次数越多倍率越高。

## 技术实现

### 双坐标体系

- **方块层**用「格」：12 列 × 20 行，负责下落、旋转、碰撞。
- **沙粒层**用「颗粒」：192 × 320，负责物理和消除判定。
- 换算：1 格 = 16 × 16 = 256 颗粒。

### 沙粒物理

每个物理步从下往上扫一行行处理，每颗沙粒：

1. 正下方空 → 往下掉
2. 正下方被占 → 随机挑一侧，看**斜下方**空不空，空就溜过去

这就是 45° 休止角的成因，也是沙堆自然塌落的原因。

### 消除判定

用洪泛填充（flood fill）找出同色连通块，记录该块的 `minX` / `maxX`；当 `minX === 0 && maxX === W-1` 时整块清除。

**判定时机**：连续 3 个物理步没有任何颗粒移动（完全静止）后才判定，避免半空中误消。

### 渲染

每帧把 192×320 的颗粒网格写进 `ImageData`，再以**最近邻**放大到画布（`imageSmoothingEnabled = false`）。比逐格 `fillRect` 快得多，边缘天然是硬像素。

每颗沙粒按哈希从「主色 / 暗部 / 高光」三档里取色，所以沙堆表面有颗粒噪点质感。

### 点阵数字

倒计时数字**不用任何字体**，是 5×7 点阵画在 canvas 上的，每格 18px。所以断网、无字体也能正常显示。

### 稳定性措施

- `frame()` 外层 try/catch，异常会显示在 overlays 上而不是静默冻结
- rAF 看门狗：0.7 秒没有跑起来就切定时器驱动
- 所有 DOM 引用判空，缺标签不会把游戏带崩
- 启动进度写进 DEBUG 行（`boot1` → `boot4:raf`）

## 调参提示

### 沙子摊多开（MAX_SLIDE）

单位是**颗粒**（1 格 = 16 颗粒）。这是「每颗粒子最多横移几次」的累计额度：

| 值 | 效果 |
|---|---|
| `0`（默认） | 不限流，沙子摊到两边，能凑出满宽消除 |
| `8` | 明显更黏，堆成锥形山，**几乎无法消除** |
| `16` | 半山 |
| `32` 以上 | 基本等同不限流 |

⚠️ 别设得太小：从高处滚下来的粒子每下一行都要消耗额度，额度不够时长坡上的沙子会半途停住，堆成山峰——山脚够不到左右墙，就永远消除不掉。

调之前可以跑诊断：

```bash
node tests/diag.js
```

它会连续在正中间丢 15 块，对比 `MAX_SLIDE = 0/8/16/32/99` 的堆高、底宽和坡度。

### 颗粒精细度（SUB）

| SUB | 颗粒网格 | 每格颗粒 | 单个四格方块 |
|---|---|---|---|
| 8 | 96 × 160 | 64 | 256 颗粒 |
| 12 | 144 × 240 | 144 | 576 颗粒 |
| **16（当前）** | **192 × 320** | **256** | **1024 颗粒** |

⚠️ SUB=16 时每帧要处理 61,440 个格子，桌面浏览器没问题，**手机可能掉帧**。卡的话优先降到 12 或 8。

### 其他

| 想改什么 | 位置 |
|---|---|
| 沙子流速 | `game.js` `STEP`（**调大 = 变慢**，调小 = 变快） |
| 倒计时大小 | `game.js` `drawCountdownDigit()` 里的 `var px = 18` |
| 颜色数量 | `core.js` `COLORS`（加减都行，方块颜色自动循环） |

## 已知限制

- 沙粒是格子化的沙堆模型（45° 休止角），不是真实刚体物理。
- 方块下落时仍是硬方块，落地那一瞬才溶解——这是为了保留俄罗斯方块的可操作性。
- 没有 Hold（暂存），只有一个下一块预览。
- 最高分存在浏览器 `localStorage`，清缓存或换浏览器会丢。
- 12 列之后需要跨 192 颗粒才能消除，比 10 列时明显更难。
